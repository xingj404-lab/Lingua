# Lingua for Mac

以文本、图片 OCR 翻译和人工审校为中心的原生 macOS 翻译工作台。SwiftUI + Apple Vision + 应用内 MLX Swift；不包含语音或对话翻译。

## 已实现

- 统一翻译工作区：文字输入与图片 OCR 共用原文区；可拖入图片、TXT / Markdown，或通过「导入」菜单选择；也可在原文框按 ⌘V 粘贴剪贴板截图。图片识别后展示紧凑附件，点击附件查看原图并缩放，移除图片可保留文字。
- 领域与风格收进「翻译选项」，原文 / 译文双栏编辑，8 种语言选项，自动识别原文语言（交给模型）。
- 通用、技术、学术、商务、法律领域提示与忠实 / 自然 / 正式风格。
- 应用内 MLX 模型下载、加载本地目录、卸载、字节进度、模型总大小、已下载大小、实时速度、当前文件、缓存复用量、流式译文与取消。
- 模型下载源可选 Hugging Face 官方、HF-Mirror 国内镜像（首次默认）和自定义 HTTPS 根地址；提供模型文件页下载链接。实际 Hub 元数据与权重请求使用同一选定源，不通过修改全局环境变量实现。
- 可选远程 / 本机 OpenAI 兼容 API 服务：远程地址须为 HTTPS，本机 loopback 可用 HTTP；API Key 使用 Bearer 认证，可按 API 根地址保存至应用本地存储。禁止 HTTP 重定向。
- PNG / JPEG / HEIC / TIFF 图片导入与拖入，Vision OCR；先校正文，再翻译。处理第一帧，暂不重排原图。
- 术语表提示、数字与术语遗漏提醒；这些约束不是准确性保证。
- 最近 100 条本地记录、搜索、重新打开、TXT / Markdown 文本导入、复制与 TXT 导出。
- 长文本有界分块、24,000 字符输入限制；取消 / 失败 / 截断不作为完整结果保存。
- ChunUI 风格的 macOS 适配：单一粉色强调、语义灰阶、13 / 17 / 24 字号、连续圆角和微拟物按钮。ChunUI 当前是 iOS / UIKit 包，因此这里用原生 SwiftUI 重建风格，不导入不兼容的 UIKit 组件；业务图标为统一的原创线图标。

## 构建与运行

要求 Apple Silicon Mac、macOS 14+、Xcode 26+ / Swift 6.2+（实际使用 Xcode 27 工具链验证）。应用内 MLX 仅适合 Apple Silicon；Intel 可考虑本机外部服务，尚未验证。

```sh
./scripts/build-app.sh
open build/Lingua.app
```

也可在 Xcode 中打开 `Package.swift`，选择 `LinguaMac` scheme，使用 My Mac 构建。**完整 MLX 构建须用 Xcode / xcodebuild**，`swift build` 不会编译 MLX 所需的 Metal shaders。

进入「设置」的本地模型库，可看到已适配的 Hy-MT2-1.8B-4bit 与 Qwen3-0.6B / 1.7B / 4B-4bit。内置 Hy-MT2 无需下载；其他模型逐项显示已下载或未下载状态。点击「下载」才开始下载，下载操作不更改当前模型；下载完成后点击「使用」切换。下载源支持 Hugging Face、HF-Mirror 及自定义镜像。仅支持库中模型，不支持导入文件夹、自定义模型仓库或手动下载后指定路径。已安装文件继续离线复用。

「API 服务」模式填写服务提供的 API 根地址（通常以 `/v1` 结尾）、实际模型 ID 和 API Key。兼容 `chat/completions` 与 system / user 指令，远程地址需 HTTPS；本机服务可使用 `http://127.0.0.1:8080/v1`。根地址不要包含 `/chat/completions`，应用会追加该路径。点击翻译后原文及相关术语会发送到所配置的服务；仅支持该兼容协议，并非所有厂商原生 API。Key 默认为本次会话使用，点击「保存」后持久化至应用本地存储，不存入 UserDefaults 或翻译记录；清空 Key 后点击保存可移除对应凭据。切换服务地址会清空会话 Key，并读取新地址对应的已存凭据。应用不自动启动外部服务。

```sh
./scripts/check.sh
```

HTTP 接口测试使用 Python 3 标准库创建临时本机服务；Python 不是应用运行依赖。这个检查不下载模型，编译 UI 与通用服务适配层，测试分块无字符丢失、输入校验、HTTPS / loopback 地址校验、术语提示、校对提示、持久化、真实图片 OCR、未加载模型的错误处理、API Bearer 认证 / HTTP 合约 / 截断 / 重定向拒绝、镜像地址与模型仓库链接、真实分段传输的字节进度 / 速度、无 Hub 缓存元数据的普通文件下载、完整缓存离线复用、取消传输及损坏文件校验。完整 MLX 构建还需要通过 `scripts/build-app.sh` 验证；实际翻译质量需另行评测。

打包后可执行 `build/Lingua.app/Contents/MacOS/LinguaMac --verify-runtime` 检查包内 MLX Metal 运行，不下载权重。

## 使用与数据

快捷键：⌘ Return 翻译、⌘ N 新建、⌘ O 导入文本、⇧⌘ O 导入图片、⇧⌘ C 复制译文、⇧⌘ S 导出、⌘ , 模型设置。

原文 / 译文与术语表保存在 `~/Library/Application Support/LinguaMac/workspace.json`，普通 JSON，无云同步。模型文件保存在 `~/Library/Application Support/LinguaMac/Models`，按下载源、仓库及固定 revision 隔离。下载到明确目录后检查文件大小与 LFS SHA-256，再从该目录加载，避免依赖 Hub 缓存路径解析。完整缓存可离线加载，重试复用已完成且校验通过的文件。原图只保留在当前会话，剪贴板识别的临时文件在识别结束后清理；历史记录保存 OCR 文字，不复制原图。首次下载模型连接所选下载源，OCR 和本地模型翻译在本机运行；API 模式会将原文及相关术语发送到所配置的服务。只下载公开模型，不从环境 / Token 文件读取认证信息传给镜像；本地模型仅支持模型库中已适配的型号，不支持导入其他模型文件。

[HF-Mirror 使用说明](https://hf-mirror.com/)：镜像是第三方公益服务，不是 Hugging Face 官方服务。已通过镜像实际下载默认模型的完整 2.28 GB 文件，完成大小 / LFS SHA-256 校验并加载，验证了一次中文到英文的本地翻译。

## 模型选择与限制

[模型调研](docs/model-research.md) 包含 Offgrid 身份核查、TranslateGemma / Qwen / NLLB / Marian、MLX / Core ML、授权与评测计划。

本版原生接入 Qwen 通用指令模型和混元专用翻译模型。混元按 `hunyuan_v1_dense` 配置选择 user-only 翻译提示、相关术语前缀与官方建议采样参数，独立 `.jinja` 模板随模型下载。模型菜单的大小是下载量而不是运行内存，下载期间以仓库当前元数据为准。选用新模型后需要先加载，已下载模型文件分别缓存；切换不会删除原有缓存。小型模型调研见 [small-model-research.md](docs/small-model-research.md)。TranslateGemma 4B / 12B 是下一步专用翻译候选，但其消息格式不能直接套用本版通用提示；还需要专用模板与加载器适配。Core ML 当前完成调研，未实现运行后端。Apple Translation 是报告提出的低资源备选，当前代码未接入。

未做 Offgrid 对照测评或领域翻译盲评，不宣称模型比 Offgrid 更强。分块降低内存占用，但块之间不传递全文上下文。术语表暂无语对分组 / 变形匹配，数字检查是字符串启发式。OCR 阅读顺序适合普通页面，复杂多栏 / 表格需人工整理。模型的思考模式被关闭，但任意自定义 checkpoint 的输出协议仍需逐个验证。

## API 配置与点击区域（2026-10-08）

API 页面提供 OpenAI（ChatGPT）、DeepSeek、自定义三种服务商。模型 ID 由用户直接填写；服务商切换保留各自地址与模型配置。旧本机服务配置迁移到自定义，保留地址和模型；凭据按地址存入应用本地目录。自定义可连接兼容的远程或 loopback 服务。

配置依据：[OpenAI GPT-4.1 mini 文档](https://developers.openai.com/api/docs/models/gpt-4.1-mini)、[DeepSeek 首次调用](https://api-docs.deepseek.com/)、[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。未使用真实远程 Key 调用或消耗账户额度；请求构造 / 参数范围由测试验证。

主按钮、侧边栏、切换控件、文字按钮、图标按钮与历史记录按钮统一在完整布局范围定义点击形状，轻量控件额外扩大留白。验证点击按钮边缘和侧边栏右侧空白可触发操作。

翻译页提供“本地模型 / API 服务”切换并记住用户选择。设置页的两个分页只用于浏览配置，不改变翻译方式；用户点击“开始翻译”或“使用此 API 翻译”才启用对应方式。下载 / 加载模型、查看服务商配置及请求失败均不会自动切换翻译方式，也不会自动降级到其他服务。

本地模型区分文件与内存状态：重启后已下载文件显示“已下载 · 未加载”，按钮为“加载模型”；内存就绪后显示“开始翻译”。界面通过清单与文件大小快速识别缓存，加载前仍执行完整校验。官方源与国内镜像的旧缓存以及包含仓库 ID 的新缓存可跨源复用，无需重复下载完整模型。回归测试覆盖断网加载、跨源复用、不同仓库隔离及不完整文件拒绝；用户的 Hy-MT2 缓存约 1.02 GB 已通过大小与 SHA-256 校验。

原文输入框支持 Enter / 数字键盘 Enter 开始翻译，Shift+Enter 换行；中文输入法存在组合文字时交由输入法确认，不触发翻译。译文框仍使用普通换行行为，Command+Enter 快捷键保留。仅在满足翻译条件时提交。

本地运行监控：底部每秒采样 App 驻留内存、进程 CPU（单核 100%，多核可超过 100%）以及 MLX 活跃分配与缓存。MLX 内存与进程内存存在重叠，不能相加；CPU 不代表 GPU 利用率。生成期间每 0.3 秒用分词器对当前输出重新计数并标记为估算，完成后采用 MLX 的输入 / 输出 token 与生成耗时统计。多段翻译累计统计，翻译耗时包含输入处理与段间开销，token/s 以生成耗时计算。

翻译完成仅更新底部状态，不再展示重复的“译文可直接编辑”提示条。主界面的技术标签使用“本地模型 · 离线翻译”和“模型内存”，鼠标提示说明指标含义；兼容模型文件格式的 MLX 名称仍保留在模型配置与说明中。

加载时显示模型 ID、阶段、已用时间与本机装载说明，完成后保留耗时。Workspace 和引擎都保护已加载实例，同一模型重复加载直接复用，普通翻译仅创建新的独立文本上下文，不重新加载模型权重。本次 App 运行中模型驻留；重启、卸载或更换模型后才需要重新装载。`LinguaMac --verify-cached-model` 只使用完整本地缓存验证：Hy-MT2 装载约 2.96 秒，两次加载请求与两次翻译仅实际装载一次，未下载模型；真实输出为 `Hello.` / `Thank you.`，生成计数分别为 2 / 3 token。

## 内置默认模型与自动装载

发行 `.app` 内置 Hy-MT2-1.8B 的 4-bit 模型约 1.02 GB，首次安装即可离线使用。构建脚本从已下载且通过 SHA-256 校验的本机快照打包，不联网下载权重；构建机可通过 `LINGUA_DEFAULT_MODEL_DIR` 指定带清单的快照目录。模型文件实际位于 App 的 `Contents/Resources/BundledModels`，使用独立副本，不依赖用户缓存路径。原模型许可、转换模型卡与来源说明随模型一起打包。

启动时保留用户选择的翻译方式：本地模式自动装载所选模型，默认使用内置 Hy-MT2；API 模式不会自动切回本地。启动装载只读取本地文件，缺失或损坏时提示去模型设置选择 / 下载，不会自动发起下载。打开翻译页或从 API 切回本地也会按需装载，并复用已有内存实例。自动装载完成仅更新底部状态与耗时，不弹出常驻提示条。

模型库增加四个模型的场景介绍、体积与选择入口。Hy 的翻译专用定位和术语 / 风格支持参考[官方模型卡](https://huggingface.co/tencent/Hy-MT2-1.8B)，Qwen 的通用多语言定位参考[官方模型卡](https://huggingface.co/Qwen/Qwen3-4B)；体积取舍为产品选择建议，未宣称某个 Qwen 比 Hy 翻译更好。

验证：23 项测试通过，覆盖资源包内模型定位、仓库隔离与完整性验证。打包 App 的 `--verify-cached-model` 明确使用内置模型且完成两次翻译，仅实际加载一次。实际重启 App 自动进入“本地模型已就绪”，装载约 2.4 秒；发行包约 1 GB。

## 紧凑翻译布局与启动预热（2026-10-12）

参考用户提供的 Translator：翻译页默认收起侧栏，语言方向集中在顶栏，原文标题栏放导入、清空、翻译 / 停止，译文标题栏放复制和导出。删除底部独立翻译按钮区，保留两栏字数、快捷键与生成统计。顶部“更多”可访问术语表、记录和模型设置，左上按钮可恢复侧栏。进入翻译页时原文自动获得焦点；清空同步清除本次生成统计，不卸载模型。

加载模型后执行一次两 token 的独立预热请求，初始化输入处理与 GPU 前向 / 生成计算，然后才发布模型就绪。预热只使用固定的本地短文本，不更新译文、记录或用户上下文；加载阶段明确显示“预热模型”。重复加载同一实例跳过预热，用户翻译仍使用独立上下文。

验证脚本增加首次 / 后续完整推理耗时及实际预热次数。本机本次未复现用户的 6.3 秒首轮耗时：未预热 CLI 首轮 0.39 秒、次轮 0.23 秒；预热后 CLI 为 0.22 / 0.23 秒，预热 1.08 秒，装载与预热仅各一次。这是不同进程的本机抽样，不是严格性能基准。实际新窗口使用“迁移”做首次 Enter 翻译约 0.7 秒，再点标题栏翻译约 0.6 秒。清空、复制与导航菜单已通过 UI 验证，用户原文和译文已恢复。23 项测试及完整构建通过。

### 首条 / 空闲后翻译的后续诊断

用户澄清 App 未重启，首条仍慢。增加输入预填充、生成、首字等待与总耗时统计，底部时间可点击展开详情；“分词、界面及保存”为总耗时减去预填充与生成的剩余值。诊断中实际复现了 6.2 秒首条、0.8 秒重复请求，其中首条预填充 5.65 秒、正文生成 0.27 秒，排除了单纯重复加载和正文生成过慢。

旧预热仅使用一种输入长度，并采用温度 0 的贪心路径；实际 Hy 翻译使用 temperature=0.7、top-p=0.6、top-k=20、repetition penalty=1.05。现统一采样策略，预热短句与段落两条计算路径，每条最多 16 token；不保存预热译文和上下文。流式文字向界面发布最多约 12.5 次/秒，最后结果始终完整发布。翻译任务使用 userInitiated 优先级，推理期间通过 ProcessInfo 的 userInitiatedAllowingIdleSystemSleep 活动声明减少后台节能调度影响，完成 / 失败 / 取消后立即结束活动，不做空闲周期性 GPU 推理。

同一句“你提交的是什么版本”的 GUI 对照：更新后首次与重复均约 0.8 秒；隐藏 App 并空闲至少 30 秒，恢复前台后首条仍约 0.8 秒。该组抽样消除了此前复现的数秒首条等待，但输入长度、输出量、硬件负载仍会影响实际时间，不能承诺所有请求固定耗时。24 项测试通过（含预热与真实采样路径一致性回归），完整构建与签名检查通过。源模型仍常驻，用户原文与译文已保留。

## 自动双向翻译

针对聊天时交替复制发言与来信的工作流，新增“自动双向 / 固定方向”菜单。默认自动双向，配置“我的语言 / 对方语言”（初始中文 / 英语），模式和语对保存在用户偏好中。系统在本机识别输入语言：我的语言译给对方，已识别的其他语言译成我的语言；无文字或未识别时默认译给对方，可通过方向按钮临时反转。新输入会清除临时反转，重新判断方向。模式与语对适用于本地模型及 API 请求，不引入对话历史或自动发送消息。

识别只在原文变化时执行并限制采样前 2000 字符，避免流式输出期间反复识别。两栏标题显示输入语言和本次目标，旧结果与新方向不同时显示旧结果语言。实际请求 / 翻译记录存储解析后的语言方向；从自动切到固定时保留当前解析方向。极短文本、姓名及混合语言可能存在歧义，可一键反转或使用固定模式。

启动预热扩展为中文到英文、英文到中文各含短句与段落的四个请求，参数与用户请求一致，预热不进入记录。实测两种输入交替粘贴均无需手动更改目标语言；英文到中文首条额外等待在该测试中由约 8.6 秒降至约 0.8 秒，实际耗时仍受文本与设备负载影响。27 项测试通过，含语对路由、临时反转、未知语言与真实中文 / 英文 / 混合文本识别。

## 界面语言

支持简体中文、English、日本語、한국어。在设置顶部选择“界面语言”，默认跟随系统，未支持的系统语言回退为英文。手动选择会保存并即时生效；界面切换不改变翻译语言、模型、原文、译文或本地记录，也不重新加载已驻留模型。菜单标签、设置、模型介绍、OCR/下载/加载状态、校对提示和应用错误信息使用统一资源；第三方服务返回的原始错误保留原文。

资源位于 `Sources/TranslationCore/Resources/InterfaceStrings.json`。新增文案时同步提供英文、日文、韩文，并保持 `%@` 动态参数顺序与数量一致。推理提示词、持久化枚举值、模型 ID 和用户输入不依赖界面语言。
